## 🌟 The Philosophy Behind the Workbench

Most save editors are transactional tools. You click a button, a number changes, you close the window. The **Chrono Tinkerer's Workbench** rejects that coldness. We believe a save file is a diary — a record of decisions made at 2 AM, of fights won by a single pixel of health, of the exact moment you decided to spec into charisma instead of strength.

This project was born from a simple observation: players rarely want to *cheat* the game. They want to *understand* it. They want to see the machinery behind the curtain and, occasionally, nudge a gear or two so the story matches the one in their head.

So we built a workbench, not a wand. It's deliberate. It's considered. And it's yours.

---

## 🎯 What This Project Does

The Workbench reads, interprets, and rewrites save files generated by **Punch Club: The Dark Fist**. It presents their contents through a human-readable interface, allows structured modification, and writes back a fully valid save that the game will happily load.

Think of it as a translation layer between the raw byte soup the game writes and the narrative you actually experience. Under the hood, it parses a documented schema, validates every field, and only then allows commits back to disk. Nothing is silent, nothing is hidden.

At a high level, the Workbench enables:

- **Inspection** of every tracked stat, flag, and relationship value.
- **Editing** of character progression, finances, reputation, and story state.
- **Snapshots** so you can trial a change and roll back instantly.
- **Diff view** between two save states, ideal for understanding how in-game actions translate to data.
- **Batch operations** for players managing multiple playthroughs.

## 🧩 Feature Constellation

Here's a constellation of what ships in the current build, written from the perspective of a player who actually uses it rather than a spec sheet nobody reads.

- 🌌 **Schema-Aware Parsing** — We map every byte we understand to a named field. No guessing, no "unknown offset 0x4A".
- 🕰️ **Timeline Snapshots** — Save up to 50 named snapshots per profile. Rewind to any of them. Like bookmarking chapters in a novel.
- 🔍 **Semantic Diff Viewer** — Compare two saves side by side and see exactly which decisions diverged.
- 🧮 **Stat Sandbox** — Preview the downstream effects of a stat change before committing it.
- 🗂️ **Profile Manager** — Handle multiple fighter profiles without breaking a sweat.
- 🧭 **Story Flag Navigator** — Toggle narrative branches with descriptive labels pulled from the game's own dialogue strings.
- 💰 **Economy Console** — Adjust cash, debt, and investments with soft caps to avoid numerical absurdity.
- 🧬 **Skill Tree Mirror** — Rebuild a character's skill layout from scratch.
- 🩹 **Auto-Repair** — Detects corrupted or truncated saves and offers a reconstruction path.
- 📤 **Export to JSON** — Dump the entire save to a structured, readable format for archival or analysis.
- 📥 **Import from JSON** — Bring a diverged save back under the workbench's care.
- 🔔 **Change Log** — Every mutation is timestamped and reversible within the session.
- 🧱 **Plugin Hooks** — Extend the workbench with your own modules if you're that kind of tinkerer.

## 🖥️ Responsive Interface Design

The Workbench was designed for a world where screens come in every shape. From a 13-inch ultrabook to a 49-inch ultrawide, from a tablet propped against a coffee mug to a modest laptop running Linux Mint, the interface reflows gracefully.

We use a grid-based layout with breakpoints tuned to real devices rather than theoretical ones. Panels collapse into drawers on narrow viewports, the diff viewer switches to a stacked mode below 900 pixels, and every interactive element respects a minimum touch target of 44 by 44 logical pixels. Keyboard navigation is first-class: you can drive the entire application without ever touching a mouse, which makes it a pleasant companion for streamers and accessibility-focused users alike.

We also honor system-level preferences — dark mode, reduced motion, and high contrast are all respected out of the box. Because a tool you stare at for hours should never fight you.

## 🛠️ Core Modules

The codebase is arranged around five load-bearing modules. Understanding them helps you navigate the repository and, if you choose, extend it.

- **`parser/`** — Byte-level readers and writers. This is where we speak the game's native tongue. Contains the schema definitions, offset maps, and integrity checks.
- **`model/`** — The semantic layer. Converts raw fields into meaningful objects like `Fighter`, `StoryBranch`, `Economy`, and `Inventory`.
- **`editor/`** — The mutation engine. Every action a user takes passes through here, where it's validated, logged, and committed.
- **`ui/`** — The presentation layer. Built with an eye toward clarity and calm. No flashy animations that distract from the data.
- **`plugins/`** — The extension surface. A stable API for third-party modules, plus a handful of first-party examples to learn from.

Each module has its own test suite, and the boundaries between them are enforced with strict import rules. You can replace any layer without rewriting the others.

## 📦 Project Structure

A bird's-eye view of how the repository is organized, for the curious and the contributing.

- **`docs/`** — Long-form documentation, schema references, and architectural notes.
- **`src/`** — All first-party source code, organized by the modules described above.
- **`tests/`** — Unit, integration, and golden-file tests. The golden files are real save snapshots with known-good parses.
- **`locales/`** — Translation files, one per locale, plus the extraction and validation scripts.
- **`themes/`** — Theme definitions, from the default "Midnight Ring" to community contributions.
- **`examples/`** — Sample plugin modules and JSON exports to learn from.
- **`scripts/`** — Developer convenience scripts: linting, formatting, and release packaging.
- **`assets/`** — Icons, fonts, and other static resources used by the interface.

The layout is intentionally flat enough to browse on GitHub without a map, but deep enough that a monorepo-weary contributor will feel at home.

## 🚀 Getting Started (The Friendly Path)

The Workbench is distributed as a portable application bundle and as a source tree for those who prefer to run from the metal. The portable bundle is a self-contained executable that requires no system-wide dependencies — unzip, launch, and you're in.

The source path is meant for contributors and the perpetually curious. It assumes a modern runtime of your chosen flavor, a working knowledge of virtual environments, and a mild tolerance for reading build scripts. Setup is scripted: a single `bootstrap` script provisions the environment, fetches dependencies, and warms the local cache.

Before your first edit, we strongly recommend creating a snapshot of your save through the Workbench itself. This gives you a known-good baseline to return to if experimentation gets wild.

## 🧪 Testing & Verification

We take save-file integrity seriously. A save editor that corrupts save files is not a save editor — it's a griefing tool with a nice interface.

To prevent that outcome, the project maintains a three-tiered testing strategy:

1. **Unit tests** verify that individual parsers and validators behave as documented.
2. **Golden-file tests** load real save snapshots, parse them, write them back, and compare the byte-for-byte result against the original. If a round-trip isn't lossless, the test fails loudly.
3. **Integration tests** drive the full editor through scripted scenarios — edit a stat, save, reload, confirm — to catch regressions that unit tests miss.

We run the entire suite on every pull request across three operating systems and two runtime versions. Green checkmarks are not decorative here; they're the difference between a save you keep and a save you mourn.

## 🎨 Themes & Visual Language

The Workbench ships with a default theme called **Midnight Ring** — a low-contrast dark palette with amber accents, inspired by the glow of a venue at 3 AM. It's easy on the eyes during long editing sessions and pairs well with the schema views.

Alternative themes include **Gym Whites** (a bright, paper-like theme for daylight work), **Neon Alley** (a higher-contrast theme for accessibility), and **Sepia Tape** (a warm, archival theme for that nostalgic touch). Community themes are drop-in files placed in the `themes/` directory, and the in-app theme picker reloads them live.

The visual language overall is minimalist: generous whitespace, monospaced fonts for numeric fields, and a consistent icon set. We resisted the temptation to festoon the interface with gradients. Data deserves clarity.

## 🔐 Safety, Ethics & Data Stewardship

The Workbench exists in an ethical space that we want to be explicit about. It is a tool for personal, offline use on save files you own, created by playthroughs you made. It is not designed, and will not be adapted, to interact with other players, online services, or the game's developers' infrastructure.

Before every write operation, the Workbench:

- **Backs up** the original save to a timestamped sibling file.
- **Validates** the resulting save against the schema.
- **Simulates** a load cycle using an internal model to catch structural issues.
- **Logs** the entire operation to a session audit file that you can review at any time.

If any of these steps fail, the write is aborted and the original is left untouched. We'd rather you lose an edit than lose a hundred hours.

We also invite users to treat saves as personal archives. Export to JSON, keep versions, share your own snapshots with friends if you like — but respect the intent of the game's designers when sharing those exports publicly. This is a preservation tool, not a spoiler distribution service.

## 🤝 Contribution Guide

Contributions are warmly welcomed, whether they're code, translations, documentation, or a well-argued bug report. Here's the short version of how to get involved:

- **Open an issue first** for anything non-trivial. It saves everyone time and prevents duplicate work.
- **Fork and branch** with a descriptive name. `fix/diff-viewer-alignment` beats `patch1`.
- **Write tests** for behavior changes. If it's not tested, it's not done.
- **Run the linter and formatter** before pushing. The CI will tell you anyway, but it's kinder to beat it to the punch.
- **Sign off on commits** to indicate you agree to the project's contribution terms.
- **Be kind** in reviews. Everyone here is a volunteer.

For translations specifically, open a locale file, translate the strings you're confident about, and mark the rest as `untranslated`. A partial translation is infinitely better than none.

## ❓ Frequently Asked Questions

**Is this compatible with every version of the game?**
We support the currently distributed version and the immediately preceding one. Older versions may parse but are not guaranteed to write cleanly. The Workbench will warn you if it detects an untested version.

**Will using this break my achievements?**
That depends entirely on the game's own detection systems and is outside our control. We make no promises either way. The Workbench is a data tool, not an achievement manager.

**Can I use this on a save I received from a friend?**
You can, but we encourage you to think carefully about whose story you're editing. Saves are personal artifacts.

**Do I need programming knowledge to use it?**
Not at all. The Workbench is designed for players first. The source path exists for those who want it, not because it's required.

**How do I report a bug?**
Open an issue with the save file attached (after backing it up locally first) and a description of what you expected versus what happened. Redact anything you're not comfortable sharing.

**Is there a mobile version?**
The responsive web interface works on tablets and phones in a pinch, but the desktop application remains the primary experience.
